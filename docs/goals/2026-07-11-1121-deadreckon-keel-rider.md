## Posture (decided — do not redesign)

- **Maturity stays stable** (lands under a `Keel` CHANGELOG section).
- **Byte-identical on disk.** The five per-run JSONL files (`events.jsonl`, `spend.jsonl`, `traces.jsonl`, flight ledger, narrative snapshots) keep their exact paths and serialized forms. - **Dependency law for the new crate:** serde, serde_json, schemars, chrono, thiserror. NO tokio, NO I/O, NO dependency on any deadreckon crate. Everything else depends on it; it depends on nothing internal (codex's protocol-crate rule).

- **No `PipelineState` schema changes.** `PipelineState` itself does NOT move into the protocol crate in this slice (it is state, not wire; moving it is a V1 decision).

- **Edits stay inside `/Users/gdc/deadreckon`.**

## Data model

### LedgerItem (the union; wire forms unchanged)

```rust
#[derive(Serialize, Deserialize, JsonSchema)]
#[serde(tag = "kind", rename_all = "snake_case")]
pub enum LedgerItem {
    Event(RunEvent),            // exact type moved from core::events
    Spend(SpendRecord),         // moved from core (state.rs vicinity)
    Trace(TraceRecord),
    Flight(FlightEvent),
    NarrativeSnapshotRef(NarrativeSnapshotRef), // pointer, not the snapshot body
    #[serde(other)]
    Unknown,
}
```

CRITICAL: the five files do NOT gain a `kind` wrapper on disk today. Each file
keeps serializing its bare line type (`RunEvent` etc.). `LedgerItem` is the
in-memory/union vocabulary (readers that ingest mixed sources, RunView,
future single-ledger) plus the schema surface. A `LedgerFile` enum maps file →
line type → LedgerItem constructor, so `policy.rs` and readers speak one
language while bytes stay put.

### policy.rs (pure; today's implicit rules made explicit)

```rust
pub fn ledger_file_for(item: &LedgerItem) -> Option<LedgerFile>;   // None = not persisted
pub fn is_persisted(item: &LedgerItem) -> bool;
pub fn redact_for_persistence(item: LedgerItem) -> LedgerItem;     // e.g. gate-nonce scrubbing stays centralized
```

Every writer call site routes through the policy before appending. Behavior
today is the spec — the policy functions must reproduce current persistence
decisions exactly (fixture-verified), they just make them one place.

### Schema generation

`schema.rs` exposes `pub fn all_schemas() -> Vec<(name, RootSchema)>`. A test
in the protocol crate renders each to pretty JSON and compares against
`docs/schemas/<name>.schema.json`; regeneration is
`DEADRECKON_UPDATE_SCHEMAS=1 cargo test -p deadreckon-protocol` (mirroring the
goldens' update-flag convention).

## Rewire rules (behavior-preserving)

- Move types with `pub use deadreckon_protocol::…` re-exports at their old
  paths in deadreckon-core so downstream code compiles unchanged in the same
  phase; delete the re-exports only in the final rewire phase (no permanent
  compatibility shims — the workspace has no external consumers).
- Readers to rewire: `run_view.rs` (the five-way join), attach JSONL tails,
  `history grep`, verdict/doc projections. Writers: `append_json_line` call
  sites in core/runtime.
- Public-surface baseline (`tests/.public-surface-baseline`) will move —
  update it deliberately in the same commit as each visibility change, never
  as an afterthought.
