# deadreckon — Polyglot Done-Contract Rider (a non-hollow gate for every language)

This rider holds the prescriptive constraints for the goal at
`/Users/gdc/deadreckon/docs/goals/2026-06-25-1421-deadreckon-polyglot-gate-goal.md`.
It supersedes nothing in prior riders (tamper-evident, composable-seams,
stable-readiness, live-narrator, orchestrate-campaign-narration); their
invariants still apply. This rider adds a **deterministic detection floor**
that compiles a real default `acceptance.yaml`, an **optional, operator-approved
inference path** for unknown trees, and **deterministic cross-language tamper
coverage**.

**All paths absolute.** Source `/Users/gdc/deadreckon`, runtime `~/.deadreckon`.

## Posture (decided — do not redesign)

- **Maturity stays stable** (0.3.1 shipped; lands under a `Polyglot` CHANGELOG section).
- **No `PipelineState` / `AcceptanceMarker` / `AcceptanceCheck` schema changes.** The five existing `AcceptanceCheck` variants (`CargoTest`, `FileExists`, `ContentMatch`, `BuildSuccess`, `Shell`) are sufficient — non-Rust defaults compile to `Shell { command, cwd, must_pass }`. Adding a variant is out of scope; if a phase proves one unavoidable, log it in V1-CANDIDATES and continue with `Shell`.
- **The gate's trust contract is untouched.** Nonce isolation, `marker_signature`, the dr-gate subprocess boundary, and `validate_acceptance_marker` are not modified. Detection runs *before* checks are evaluated and only changes *which* checks compile when no operator `acceptance.yaml` exists.
- **The deterministic floor is the only thing that signs a marker unattended.** Inference (the provider path) NEVER produces the contract that signs a marker without explicit operator approval, and never runs under `--yes`/`--quiet`/`--json`/non-TTY. This is the load-bearing trust rule of the whole slice — the gate is the trust boundary, so a model's proposal must pass through a human before it can define "done".
- **Detection never overrides an operator spec.** If `acceptance_spec_path_for_run_root` already has a spec, `compiled_acceptance_checks` returns it verbatim — detection/inference only fill the no-spec case.
- **No `git push`.** Phased local commits only.
- **No V1 invention.** Languages beyond the P-scoped set, monorepo/multi-package contracts, multi-command test pipelines, and inference-without-approval go to V1-CANDIDATES.
- **Edits stay inside `/Users/gdc/deadreckon`.**

## Data model (files, not fields)

No new durable struct fields. One generated artifact (already-defined path):

`<run_root>/gate/acceptance.yaml` (via `acceptance_spec_path_for_run_root`) — when detection or approved inference fires, the compiled contract is serialized here in the YAML shape `parse_acceptance_checks` already reads, so operator, `verdict`, and tamper see exactly the contract that ran. The generated spec carries a leading provenance comment:
- `# generated by deadreckon detect: <kind>` for a deterministic floor result, or
- `# proposed by deadreckon --infer-contract (approved <ISO8601>): <model>` for an approved inferred result.

A `ContractSource` enum (`Detected | Inferred | Operator`) is computed in-memory and threaded into preview/verdict text; it is NOT persisted as a struct field — the comment header is the durable record.

## Detection floor (the spec — match it in code)

A new module `/Users/gdc/deadreckon/crates/deadreckon-core/src/acceptance_defaults.rs`:

```
enum ProjectKind {
    Rust, Node(PackageManager), Deno, Go, Python,
    Elixir, Dotnet, Jvm(BuildTool), Ruby(RubyRunner), Php(PhpRunner),
    ScriptRunner(Runner), Unknown,
}
enum PackageManager { Npm, Pnpm, Yarn, Bun }
enum BuildTool { Maven, Gradle, GradleWrapper }    // pom.xml / build.gradle[.kts] / ./gradlew
enum RubyRunner { Rspec, Minitest, Rake }
enum PhpRunner { Composer, Phpunit }
enum Runner { Make, Just, Task }                    // Makefile / justfile / Taskfile.yml
enum ContractSource { Detected, Inferred, Operator }

fn detect_project_kind(working_dir: &Path) -> ProjectKind
fn default_checks_for(kind: &ProjectKind, working_dir: &Path) -> Vec<AcceptanceCheck>
fn detection_caveat(kind: &ProjectKind) -> Option<String>   // Some(..) only for Unknown / unrunnable
```

Detection order (first match wins; deterministic, total, no network, no subprocess):

| # | Sentinel (in working_dir) | Kind | Compiled default check (`Shell` unless noted) |
|---|---|---|---|
| 1 | `Cargo.toml` | Rust | `CargoTest { args: [], must_pass: true }` (unchanged path) |
| 2 | `package.json` with `scripts.test` | Node(pm) | `<pm> test`; pm from lockfile: `bun.lockb`→bun, `pnpm-lock.yaml`→pnpm, `yarn.lock`→yarn, else npm |
| 3 | `deno.json`/`deno.jsonc` | Deno | `deno test -A` |
| 4 | `go.mod` | Go | `go test ./...` |
| 5 | `pyproject.toml`/`setup.py`/`setup.cfg` AND (`tests/` dir or any `test_*.py`/`*_test.py`) | Python | `python -m pytest -q` |
| 6 | `mix.exs` | Elixir | `mix test` |
| 7 | `*.csproj`/`*.fsproj`/`*.sln` | Dotnet | `dotnet test` |
| 8 | `pom.xml` | Jvm(Maven) | `mvn -q test` |
| 9 | `build.gradle`/`build.gradle.kts` | Jvm(Gradle\|Wrapper) | `./gradlew test` if `gradlew` present else `gradle test` |
| 10 | `Gemfile`/`Rakefile`/`spec/` | Ruby(runner) | resolved (below) |
| 11 | `composer.json` with `scripts.test` | Php(Composer) | `composer test` |
| 12 | `phpunit.xml`/`phpunit.xml.dist` | Php(Phpunit) | `vendor/bin/phpunit` if present else `phpunit` |
| 13 | `Makefile`/`makefile`/`GNUmakefile` with a `test:` target | ScriptRunner(Make) | `make test` |
| 14 | `justfile`/`Justfile` with a `test` recipe | ScriptRunner(Just) | `just test` |
| 15 | `Taskfile.yml`/`Taskfile.yaml` with a `test:` task | ScriptRunner(Task) | `task test` |
| 16 | `package.json` without `scripts.test` (sole signal) | Node + caveat | `FileExists {working_dir}` + caveat "package.json has no test script" |
| 17 | none of the above | Unknown | `FileExists {working_dir}` + caveat "no test contract detected" |

**Resolution rules for the ambiguous kinds (deterministic, documented, previewed):**

- **Ruby** sub-order: `spec/` dir AND `rspec` in `Gemfile.lock` → `bundle exec rspec`; else a `Rakefile` with a `test` task → `bundle exec rake test`; else `bundle exec rake`. The chosen command is shown in the preflight preview so the operator can override with `--acceptance`. (Substring scan of `Gemfile.lock`; no bundler crate.)
- **PHP** sub-order: `composer.json` `scripts.test` → `composer test`; else `phpunit.xml[.dist]` → `vendor/bin/phpunit` (or `phpunit`).
- **JVM**: `pom.xml` → Maven; `build.gradle[.kts]` → Gradle, preferring `./gradlew` when the wrapper exists (reproducible toolchain) else `gradle`. If both `pom.xml` and a Gradle file exist, Maven wins (lower #).

Notes:

- **Script-runner parsing is a textual, deterministic scan** — a `test:` target in a Makefile, a `test` recipe in a justfile, a `test:` key under `tasks:` in a Taskfile. It does NOT evaluate the file or expand variables; it only proves a `test` entry-point exists, then compiles the canonical invocation. It is the universal catch for ecosystems not in the native table.
- **Native kinds (rows 1–12) win over script-runners (13–15)** when both are present, because the native command is more precisely scoped (a `Makefile test` in a Rust repo does not shadow `cargo test`). Among native signals, lower-numbered row wins; the resolved command is always surfaced in the preview so the operator can override.
- `must_pass: true` for all detected test commands; generated `Shell` checks set `cwd: Some(working_dir)`.
- Detection reads only file presence/contents, never executes anything (Maven/.NET/Elixir/Deno commands are fixed by sentinel presence; only Ruby and PHP do a light contents scan to resolve the sub-runner).
- Python requires *both* a project sentinel and visible tests; a bare `pyproject.toml` with no tests degrades to Unknown+caveat (a green "0 tests" is hollow).
- `detect_project_kind` is pure over the filesystem and total (always returns, never errors).

## Inference path (optional, opt-in, operator-approved)

A second module function, gated behind the `--infer-contract` flag and only reachable when `detect_project_kind` returns `Unknown` (or the Node/Python "+caveat" degraded cases):

```
async fn propose_contract(working_dir, provider_router) -> Option<ProposedContract>
struct ProposedContract { command: String, test_globs: Vec<String>, rationale: String, confidence: f32 }
```

Rules (mirror the goal-shape classifier + narrator precedent in `crates/deadreckon/src/commands/start.rs` and `crates/deadreckon-providers/src/narrator.rs`):

- Uses the cheap-model router (narrator preference order) with its own small budget; on no-provider/low-confidence/parse-failure it returns `None` and the run falls back to the deterministic caveat — inference never fails a run.
- The prompt is built from a **redacted, bounded** window: the names (not full contents) of manifest/CI/script files present, plus the first N lines of `package.json`/`Makefile`/`Taskfile`/CI YAML. Treat file contents as untrusted (prompt-injection surface) — the model proposes, it does not decide.
- The proposal is rendered as a `Shell { command, cwd: Some(working_dir), must_pass: true }` plus `test_globs` for tamper coverage, written to the generated spec with the `# proposed by … (approved …)` header **only after** the operator approves.
- **Approval is mandatory and interactive.** The proposal is shown in a preview block (command + rationale + confidence), and the run proceeds with it as the contract only on explicit confirmation. Under `--yes`/`--quiet`/`--json`/non-TTY, `--infer-contract` is a no-op that emits the deterministic caveat (inference cannot self-approve).
- An approved inferred contract is a normal generated spec from that point on: dr-gate evaluates it, signs over its real results, and tamper covers its `test_globs` — identical to a detected contract. The only difference is provenance (the header) and that a human approved it.

## Wiring (where detection plugs in)

- `compiled_acceptance_checks(run_root, working_dir)` (gate.rs:284): keep the operator-spec branch first; replace the `Cargo.toml`-else-`FileExists` tail with `default_checks_for(detect_project_kind(working_dir), working_dir)`; when the result came from detection (not an existing spec), serialize it to `acceptance_spec_path_for_run_root` with the provenance header before returning.
- `evaluate_default_acceptance` (gate.rs:388) — the no-spec path used by `dr-gate` — routes through the same `default_checks_for` set so the standalone binary and the in-process compile agree byte-for-byte. dr-gate never performs inference; it only evaluates whatever spec exists (an inferred contract is already an on-disk spec by the time dr-gate runs).
- The inference proposal+approval happens in the CLI run preflight (`crates/deadreckon/src/commands/run.rs` / `start.rs`), BEFORE the loop and BEFORE dr-gate — so the approved contract is on disk as a normal spec when the gate fires.
- `detection_caveat`/`ContractSource` thread into the run's acceptance progress + verdict text so an Unknown-kind run reads "PASSED with caveat: no test contract detected" rather than a bare green.

## Out of scope (explicitly → V1-CANDIDATES)

- Monorepo / multi-package detection (per-workspace contracts).
- New `AcceptanceCheck` variants (coverage thresholds, lint kinds — the rules gate is a separate goal).

- Languages beyond the shipped native set (e.g. Scala/Clojure/Swift/C/C++/Haskell/Dart) — reachable today via the script-runner row or approved inference; the table is extensible.

## Engineering invariants (do not violate)

- **No `PipelineState`/`AcceptanceMarker`/`AcceptanceCheck` schema changes.**
- **The deterministic floor is pure, total, and the only unattended marker-signer.** `detect_project_kind` never executes a subprocess and never errors.
- **Inference never arms the gate without explicit interactive approval**, and is a no-op under `--yes`/`--quiet`/`--json`/non-TTY. A depth test pins each of these.
- **Tamper logic is LLM-free and language-uniform** — no model in the coverage/refuse path, no language-gated early-out.
- **One depth test before each phase.** A phase whose tests were never red is suspect.
- **The generated spec is the audit record** — if detection or approved inference fires, the run MUST contain the spec it ran, with the correct provenance header.
- **No silent green** — Unknown/unrunnable kinds always carry a caveat into the verdict.

## Process invariants

- Phased local commits only. No `git push`.
- Each phase ends with its depth tests passing and a CHANGELOG entry naming the SHA.
- Fixture trees (minimal Node/Deno/Python/Go/Elixir/.NET/Maven/Gradle/Ruby/PHP/Make/just projects — usually just the sentinel file(s) + a test file) live under `crates/deadreckon-core/tests/fixtures/` or an in-test `tempfile` tree; do NOT add real toolchains to CI — depth tests assert *detection, compiled checks, inference gating, and tamper classification*, not live `npm/pytest/go/mvn/dotnet` execution. A single opt-in integration test may run a real `go test`/`pytest` behind an env guard if the toolchain is present; it must skip cleanly otherwise. Inference depth tests use a scripted/fake provider, never a live model.
- If a phase reveals a V1-architecture decision, stop and log it in V1-CANDIDATES; do not silently expand scope.
